# V4.2.3 Stardust preview validation

Stardust is an independent C stereo shimmer, selected beside Original inside SHIMMER. It uses an eight-line Householder feedback network, four input allpass diffusers per channel, two overlapping pitch-shift read heads, damping and pitch-path low-pass filtering, high-pass feedback cleanup, modulated delay reads, energy-scaled injection and finite/bounded state guards. Size, decay, pitch and all level controls are smoothed. Processing allocates no memory inside the C block loop. TYPE switches clear shimmer history and use a short transition fade. No Sinevibes code, plugin binary, artwork or preset bank is distributed.

The user-provided screenshot, manual and readable XML presets supplied a parameter reference. Pre Delay supports -1000..+1000 ms (negative delays the base path, positive delays the new send); pitch is -12..+12 ST; modulation frequency is 0.05..5 Hz. Input/Send/Return are independent. Values are not asserted to reproduce Luminance's sound.

The original native FX/reverb binary and the REVERB category/parameters are retained. Original is the default for old projects. The Original processing path invokes the unchanged native processor, with no Stardust DSP processing. Stardust invokes the same native FX with only the old shimmer contribution disabled through a read-only parameter view, then adds its own network. The existing reverb handle is not replaced/reset by type selection. The reference view does not change saved original shimmer/reverb values.

75 host tests pass, including prior app regression tests and Stardust checks for: silence, dry passthrough, positive/negative pre-delay, independent levels, decay/late energy, long tails and extreme parameter values, clearing, variable frame counts, pitch-up/down spectral bands, default Original processing, switching, and unchanged original parameter values. The C library is built for AArch64 and verified as ELF64/ARM64. Its libc/libm symbol requirements match the existing native FX baseline (GLIBC 2.17/2.27).

The original ARM application --stardust check validates the actual AudioWorker shared parameter reader, TYPE selection and all ten parameters, header/grid navigation, native processing with an actual tail, project save/load, old-project Original default, native reverb handle/parameter preservation, the mapped physical MENU shortcut and untouched X/Y events. Screenshots show TYPE above the control grid with its hint beneath it, and all ten controls visible. A/B edits TYPE only when selected; MENU directly toggles it; X remains Next FX and Y remains Fine.

The original --preview-mixer and --frozen-save regressions pass with the new hook installed: START-only SAMPLE transport, preview handoff, dry playback and the full 16-second held-input WAV export are retained. OS audio/process boundaries are mocked in application UI checks.

The optional closed-app timing probe opens no audio device, checks the app lock and writes a readable report inside grainbrick-v4. It is compatibility-tested under ARM emulation only. Emulator/host timings are not evidence of Anbernic CPU headroom. Device testing is still required for sound quality, switching behavior, full-chain load, overruns and USB latency. The profile isolates Stardust and excludes granular, other FX, tape, USB, UI and scheduler load.

The cumulative preview ZIP is virtually overlaid on complete V4.2, V4.2.1 and V4.2.2 archives and checked against every target manifest hash. Old native libraries, palette files, recording code and control mappings are not replaced. No personal data/configuration is packaged. The standalone target remains a private build artifact; only the small preview update and optional timing probe are published.


## V4.2.4 response and navigation revision

The feedback pitch projection blend is reduced from 45% to 16%, preserving more unshifted recirculation rather than increasing output gain. Size now spans a 0.2–2.3 delay multiplier (previously 0.4–1.9); the nominal decay target spans 0.25–40 seconds with a 1.4-power response (previously 0.4–20 seconds with a squared response). These are network coefficients, not promises of audible RT60. Brightness spans a 120–18000 Hz damping cutoff, and maximum modulation depth is 3 ms rather than 1.5 ms. Displayed units, button steps, Pitch/Frequency/Input/Send/Return ranges and Original/native REVERB remain unchanged. Existing Stardust percentages therefore produce a different sound.

A deterministic 0.5-second stereo noise burst, 48 kHz, maximum Size/Decay/Brightness, zero modulation, no pre-delay and +12 semitones reaches the relative -40 dB energy threshold after about 8.5 seconds versus 4 seconds for V4.2.3, using 0.5-second measurement windows. This is a synthetic comparison, not listening confirmation or a claimed match to another plugin. Wet peak/total energy in this fixture is slightly lower; no Return boost was added. A 24-second regression checks both pitch directions for a persistent late tail followed by decay, finite samples and no excessive peaks. Size at its extremes produces more than an eightfold onset-time difference. All 76 host tests pass, including the existing pitch-up/down spectral checks.

The actual ARM app regression checks physical mapped L2/R2 on every FX category, previous/next wraparound, consumed X, untouched Y events, and untouched L2/R2/X in GRAIN. Existing MENU type/project/shared-reader/reverb-preservation checks also pass. Footer hints are updated throughout FX. SAMPLE/LIVE retains input selection on L2/R2. This revision has not yet been measured or heard on the handheld; the user's 1.02 ms mean timing report was for V4.2.3 alone.


## V4.2.5 pitch-cloud revision

The internal feedback topology still uses a bounded replacement of two projected network subspaces, now with a 32% shifted blend. The audible return additionally combines the unshifted bed and the pitch-read output with power-balanced weights (0.35 and 0.93675 at normal nonzero pitch); it crossfades to the bed near zero transposition. The dry input is not pitch-shifted. This separates audible octave prominence from how aggressively the lossy pitch path replaces feedback energy. It is a sonic redesign, not just a feedback-level or Return-gain increase. No Pitch Feedback UI control was added.

The delay network now spans a 0.2–4.8 room multiplier and has longer buffers; its nominal decay target spans 0.25–60 seconds. Actual audible decay depends on damping, pitch, size and modulation and is not guaranteed to equal that target. Independent left/right read-head phases drift with slight +/-0.15% transposition detuning, keeping the pitch centered while decorrelating the stereo cloud. Depth reaches 6 ms of FDN movement (clamped against short delays), plus 12 ms at the pitch read heads, at the existing Frequency rate. Pitch-read offsets stay positive and within their allocated buffers, including maximum Depth. No allocations were added to the C audio loop. Brightness and all user parameter ranges/steps are retained.

77 host tests pass. The pitch test now also requires the shifted octave to dominate the input-note band in both directions and checks a second upward octave from recirculation. A new coherent-mono-tone check verifies stereo decorrelation, channel balance, retained mono energy and stronger modulation sidebands at high Depth/Frequency. The existing long-tail, extreme-parameter and passthrough tests still pass.

In a deterministic 48 kHz fixture at maximum Size/Decay/Brightness, zero modulation, zero pre-delay, Input 0, Return/Send 100% and +12 ST, a three-second 220 Hz tone gives a late-tail 440-to-220 Hz band ratio of +7.2 dB versus -18.9 dB in V4.2.4 (tail measured 3–7 seconds; +/-10 Hz bands). The next octave at 880 Hz is also present. The fixture's stereo correlation is approximately -0.13 versus -0.75 before; it is not widened simply by polarity inversion. A separate 0.5-second stereo-noise burst gives an approximately 11.5-second relative T40 versus 8.5 seconds previously; peak wet output is lower in that fixture. These figures describe synthetic tests, not subjective similarity to the reference plugin.

The ARM app selector/project/shared-reader/native-tail/reverb-preservation and L2/R2 navigation checks pass with this rebuilt library. SAMPLE preview/mixer transport is checked with the new build. All earlier V4.2.x complete archives can receive the cumulative overlay and match the target manifest. Device listening and processor-load validation remain outstanding for V4.2.5; the previously supplied device timing belongs to V4.2.3.


## V4.2.6 unwanted pulse and load investigation

V4.2.5's 120 ms dual read-head pitch crossfade produces tonal cancellation and a periodic envelope: at +12 ST the two-head pattern can repeat around 16.7 Hz even with Depth zero, independent of the Frequency control. This matches the reported unwanted fast tremolo. A sustained 125 Hz input at Size 50%, Decay 80%, Input 0, Return 100%, +12 ST and Depth zero reproduces approximately 42–44% normalized coherent 5–30 Hz envelope modulation in the two channels (5 ms RMS windows, settled output from seconds 4–12).

The replacement pitch stage is an independent 2048-point streaming phase vocoder with a 512-frame hop and four normalized overlapping periodic Hann windows. Both stereo channels share one packed complex forward/inverse FFT pair, with separate spectral phase/frequency histories. Spectral energy, rather than amplitudes, is redistributed when bins merge or split, avoiding a down-shift feedback gain boost. Cached twiddles and interpolated polar synthesis remove repeated trigonometric calls; the bounded phase approximation is within 4 mrad. Memory is allocated at engine creation; no allocation occurs in the C processing loop. It needs no external FFT library. Its fixed window adds approximately 43 ms in the wet pitch path; dry audio is unaffected. The pitch head crossfade and its fixed repetition rate are removed.

The return retains a small unshifted bed with a predominantly pitched cloud (power-balanced 0.2/0.979796 weights away from zero pitch). Depth/Frequency control intentional network-delay and pitch-ratio modulation. Size/Decay, navigation, the other effects, Original and native REVERB are unchanged. No Pitch Feedback control is added.

78 host tests pass, including a new 125/220/371 Hz regression limiting coherent 5–30 Hz envelope modulation to under 12% at Depth zero. The reproduced 125 Hz case falls to approximately 2.2% in both channels. The test also requires identical output for Frequency extremes when Depth is zero. Existing octave prominence, recirculation, stereo/mono, long-tail stability, control, routing and transport regressions pass. These synthetic results do not claim all texture or audible artifacts have been eliminated.

The updated native library and timing probe run under ARM emulation, and the original ARM app selector/project/shared-reader/tail/reverb-preservation/navigation regression is repeated on this library. It still uses only the original GLIBC 2.17/2.27 baseline. Emulator timings are not handheld CPU evidence. The new pitch algorithm does more work than V4.2.5; its actual device cost is not yet known. The user's approximately 50% LIVE DSP meter reading is a full render-path figure, which can include blocking USB capture inside Source.render, rather than pure CPU utilization. ## V4.2.9 wet-level and control-range calibration

The user reported that the entire shimmer and its controls remained too weak, including at full settings, and requested a stronger overall effect. Measurements identified a gain-law problem: per-line injection normalization sqrt(1-g^2) shrank as Decay increased, but the network also loses energy through pitch shifting, filtering and projected feedback. Thus long Decay starved the excitation while the dry Input stayed at full level. In a ten-second fixture at Size 50%, Pitch +12, Input 0, Send/Return 100%, wet level at maximum Decay was about -23.7 dB relative to white-noise input, -13.1 dB on a chord and -15.6 dB on a rhythmic chord.

The fix computes mean loss across the eight lines and applies one common correction sqrt((0.2 + 0.8*mean_loss)/mean_loss) to the previous injection weights. A common factor preserves their relative balance and avoids new resonance coloration. Return has an additional factor of two (6 dB) wet normalization. Feedback gain, pitch engine, delay/decay geometry and the pitched/unpitched return proportions are retained. The same maximum-Decay fixtures now measure approximately -8.9 / +1.7 / -0.8 dB wet-versus-dry: about 14.8 dB more wet presence. Noise wet level changes by only about 0.3 dB as Decay moves from minimum to maximum, instead of fading roughly 9 dB. These results are source-specific calibration figures, not a loudness guarantee for all audio.

Depth now spans a gentle lower range and a more audible upper range, using a 2.75-power curve with about +/-24 cents at 100%. Frequency remains 0.05–5 Hz. Existing Size, Decay, Pitch, Brightness, Pre Delay, Input and Send ranges/units are retained; the calibrated wet level makes their changes much more apparent. UI descriptions identify the broader upper Depth range and stronger Return. With wet active, an output knee above 0.9 approaches 0.98 smoothly for headroom. Return zero preserves exact dry bypass. The stationary bed/pulse fix remains in place; no Pitch Feedback UI control or additional FFT stage is added.

85 host tests pass. New tests check useful wet level for noise, chords and rhythmic chords; protection against send starvation at maximum Decay; meaningful endpoint contrast for all ten controls in the combined dry/wet result; high-input headroom, exact Return-zero bypass and smooth headroom engagement when Return rises from zero. Endpoint-difference RMS is approximately 0.68–1.57 times the dry reference RMS in that rhythmic chord fixture. Existing rhythmic-artifact, disabled-modulation, pitch, stereo/mono, feedback stability, parameter and transport checks pass. The modulation test no longer assumes that fast LFOs always spread more energy beyond a fixed frequency offset than slow LFOs; it requires measurable intentional modulation within the newly broader limit.

The rebuilt ARM app selector/project/shared-reader/native-tail/reverb-preservation/navigation regression and cumulative overlay hashes are verified. Original shimmer, native REVERB, other effects and controls are unchanged. The changes add no new processing stage; actual handheld sound and timing require device confirmation. No uploaded plugin or preset data is redistributed.


## V4.2.10 granular-core, onset and Brightness redesign

The user reported a late, detached wet onset, insufficient richness/width, weak dark-Brightness pitch presence and an overly distinct sine movement, while explicitly requiring a more present grain texture without increasing DSP load. Both the user and an added full original LIVE-chain test confirmed that INPUT/RETURN zero produces silence at FX MIX 100%, ruling out an app dry-bypass error for that configuration. The native regression now also verifies dry-only and wet-only output through the complete original DSPChain, with synthetic capture and real native stages.

The spectral pitch stage is replaced by eight asynchronous overlapping Hann-windowed grains per channel. Grain durations and starts vary independently with separate deterministic random streams for grain scheduling and slow motion. Read heads restart at zero window weight, and their weighted sum is normalized. No FFT or audio-rate sine modulation remains. Depth controls scatter, micro-detuning and shorter grain lengths toward its upper range; Frequency controls smooth cubic motion between irregular targets. Size also changes grain length. The two channels have independent grain schedules and small centered detuning. A calibration factor on the audible pitched return compensates for the ensemble's averaging; feedback retains the bounded unboosted grain output and the preceding 44% projection blend. No Pitch Feedback control is exposed.

A short diffused early component and an early pitched feed make the effect engage before the long network build-up. User Pre Delay still delays the send (or dry/base path when negative); it is not removed or relabeled. The first wet response now starts within the first milliseconds at Pre Delay zero, while Size still changes the later energy distribution. Brightness has a 300–18000 Hz damping range and a dark low-body shelf; the anti-alias stage is independent. Four cascaded Butterworth sections (eighth order) protect pitch-up sampling, with smooth coefficient changes and retained bright passband. Low Brightness therefore preserves pitched body rather than doubly attenuating the pitch input. Brightness up opens the air and upper shimmer. Existing gain calibration and output headroom remain.

88 host tests pass. Added tests cover immediate wet integration versus explicit Pre Delay, retained pitched body/dark-vs-bright spectral contrast, and high-frequency alias rejection while retaining the valid bright shifted band. Tests whose old expectations encoded a stationary spectral/sine engine now assess irregular grain texture: nonperiodic envelope correlation, increased grain bandwidth with Depth and small coherent sine contribution. The old fixed-head tremolo is still rejected, while aperiodic grain-level variation is permitted. Size uses the median energy time rather than first arrival because early response is an intended change. The Frequency endpoint check allows a nuanced texture change instead of requiring a large whole-signal change. Pitch octave/recirculation, stereo/mono, long-tail stability, headroom, exact Return-zero bypass, rhythmic-tail and other app regressions pass.

In controlled host thread-CPU runs at the same block size and maximum timing-probe parameters, the spectral build measured about 0.237–0.264 ms/block versus 0.164–0.217 ms/block for the grain build; the median is roughly 30% lower. These are host comparison figures, not Anbernic measurements. The rebuilt ARM library/probe run under emulation, and actual native-app selector/project/shared-reader/tail/reverb-preservation/navigation plus complete LIVE routing checks pass. Address/undefined-behavior sanitizer runs exercise 8/48/96 kHz, variable blocks, automated extremes, nonfinite input, clearing and destruction; leak detection is unavailable in the traced executor and was disabled for that run. There are no per-block C allocations.

## V4.2.11 texture control, Frequency response and dark downward definition

The user found the granular direction useful but the base texture too pronounced, Frequency difficult to hear, and -12 ST / Brightness 0 too sub-heavy and indistinct. Depth is retained as texture intensity; Frequency now drives grain scattering/movement and renewal cadence as well as the small irregular detuning. It does not impose a whole-tail sine LFO. Pitch remains the main transposition control; Send still excites the effect and Return sets wet level. The internal pitched/unpitched scalar blends are unchanged and no balance control is exposed.

Base grain durations increase to 40–110 ms before variation, with +/-10% length variation instead of +/-20%. Depth shortens grains less aggressively. The Frequency-driven wander now affects start scatter and grain length/cadence, not just tiny detuning; its logarithmic rate position scales texture cadence gradually between the slow and fast endpoints. Read changes still occur at grain boundaries with zero window weight, leaving the reverb network delays steady.

Only dark downward shifts receive the new definition treatment: the dark shelf is rebalanced away from a sub-bass boost toward low-mid body, and a small DC-filtered harmonic component derived from the wet low band provides audible upper definition. The fundamental remains down-shifted. Brightness-up response and independent anti-aliasing are retained. At steady Pitch, redundant coefficient interpolation is skipped, helping offset the cheap tone additions; there is no new grain voice, FFT or heavy processing stage.

90 host tests pass. New audio tests require a clearer Frequency-dependent texture cadence/bandwidth change and retained bass-note identity plus audible body at -12 / Brightness 0. In a sustained-note fixture, Depth 0/50/100% octave-band spread changes from about 11.75/14.57/25.0 Hz to 8.32/9.53/12.89 Hz, consistent with smoother base and upper texture. The Frequency-extreme output contrast rises from about 0.077 to 1.36 relative to wet RMS in that fixture; this includes phase/texture changes and is not a subjective loudness measure. The dark downward body-to-sub-band ratio improves from about -11.9 to -8.8 dB, while bass remains stronger than the body band.

Host thread-CPU comparisons remain in approximately the same range (roughly +/-5% across the tested Depth settings); they are not handheld measurements. Native ARM selector/project/shared-reader/tail/reverb-preservation/navigation and full LIVE routing checks pass. ## V4.2.12 independent grain and LFO controls

Stardust now exposes all thirteen controls on one screen, as requested for the handheld: Pre Delay, Size, Decay, Pitch, Brightness; Grain Size, Granular Rate, Texture Depth, LFO Rate, LFO Depth; Input, Send, Return. TYPE and its hint remain in the header. Original retains its previous layout. No Granular Mix or Pitch Feedback control is added.

Size affects the reverb network dimensions only. Grain Size sets duration from 20 to 100 ms, with independent natural +/-10% variation. Texture Depth sets scattering and micro-detuning intensity; Granular Rate controls irregular movement speed. Neither changes grain duration or renewal cadence. LFO Rate and LFO Depth independently add common sine pitch modulation to the granular read heads, including feedback and audible return, without changing the grain clock. At zero LFO Depth the sine movement is disabled. Older projects receive Grain Size 60 ms and LFO Depth zero; existing parameter keys remain compatible. The previous Brightness and dark downward definition are retained.
