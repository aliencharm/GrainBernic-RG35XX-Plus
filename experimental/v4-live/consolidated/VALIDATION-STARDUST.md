# V4.2.3 Stardust preview validation

Stardust is an independent C stereo shimmer, selected beside Original inside SHIMMER. It uses an eight-line Householder feedback network, four input allpass diffusers per channel, two overlapping pitch-shift read heads, damping and pitch-path low-pass filtering, high-pass feedback cleanup, modulated delay reads, energy-scaled injection and finite/bounded state guards. Size, decay, pitch and all level controls are smoothed. Processing allocates no memory inside the C block loop. TYPE switches clear shimmer history and use a short transition fade. No Sinevibes code, plugin binary, artwork or preset bank is distributed.

The user-provided screenshot, manual and readable XML presets supplied a parameter reference. Pre Delay supports -1000..+1000 ms (negative delays the base path, positive delays the new send); pitch is -12..+12 ST; modulation frequency is 0.05..5 Hz. Input/Send/Return are independent. Values are not asserted to reproduce Luminance's sound.

The original native FX/reverb binary and the REVERB category/parameters are retained. Original is the default for old projects. The Original processing path invokes the unchanged native processor, with no Stardust DSP processing. Stardust invokes the same native FX with only the old shimmer contribution disabled through a read-only parameter view, then adds its own network. The existing reverb handle is not replaced/reset by type selection. The reference view does not change saved original shimmer/reverb values.

75 host tests pass, including prior app regression tests and Stardust checks for: silence, dry passthrough, positive/negative pre-delay, independent levels, decay/late energy, long tails and extreme parameter values, clearing, variable frame counts, pitch-up/down spectral bands, default Original processing, switching, and unchanged original parameter values. The C library is built for AArch64 and verified as ELF64/ARM64. Its libc/libm symbol requirements match the existing native FX baseline (GLIBC 2.17/2.27).

The original ARM application --stardust check validates the actual AudioWorker shared parameter reader, TYPE selection and all ten parameters, header/grid navigation, native processing with an actual tail, project save/load, old-project Original default, native reverb handle/parameter preservation, the mapped physical MENU shortcut and untouched X/Y events. Screenshots show TYPE above the control grid with its hint beneath it, and all ten controls visible. A/B edits TYPE only when selected; MENU directly toggles it; X remains Next FX and Y remains Fine.

The original --preview-mixer and --frozen-save regressions pass with the new hook installed: START-only SAMPLE transport, preview handoff, dry playback and the full 16-second held-input WAV export are retained. OS audio/process boundaries are mocked in application UI checks.

The optional closed-app timing probe opens no audio device, checks the app lock and writes a readable report inside grainbrick-v4. It is compatibility-tested under ARM emulation only. Emulator/host timings are not evidence of Anbernic CPU headroom. Device testing is still required for sound quality, switching behavior, full-chain load, overruns and USB latency. The profile isolates Stardust and excludes granular, other FX, tape, USB, UI and scheduler load.

The cumulative preview ZIP is virtually overlaid on complete V4.2, V4.2.1 and V4.2.2 archives and checked against every target manifest hash. Old native libraries, palette files, recording code and control mappings are not replaced. No personal data/configuration is packaged. The standalone target remains a private build artifact; only the small preview update and optional timing probe are published.
